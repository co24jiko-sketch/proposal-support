# 技術提案書サポート — パイロット運用手順

最終更新: 2026-07-08（記載ルールチェック・提案の軸確定 UI に合わせて改訂）

## パイロットの目的

入札図書から技術提案書の初稿作成・記載ルールチェック・承認・PDF 出力までを、**実際の業務に近い流れ**で試し、使い勝手と不足機能を洗い出す。

## アカウント（3 ロール）

| ロール | 用途 | メール | パスワード |
|---|---|---|---|
| **担当者** | 案件作成・編集・承認申請・PDF 出力 | Supabase で個別作成（下記参照） | 作成時に設定 |
| **部長** | 1 次承認 | `manager@pilot.local` | `PilotManager2026` |
| **支社長** | 2 次承認 | `director@pilot.local` | `PilotDirector2026` |

### 担当者アカウントについて

- 担当者は **1 人 1 アカウント**（Supabase Dashboard → Authentication → Users で作成）
- 新規ユーザーは自動的に `assignee` ロールになる（`add_auth_profiles.sql` 実行済み前提）
- **自分が作成した案件だけ** 編集・アップロードできる（ヘッダーの表示名＝案件の担当者名）

### ログインできないとき

| 症状 | 対処 |
|---|---|
| 支社長ログイン失敗 | Dashboard でユーザーを削除 → 再作成（Auto Confirm）→ SQL で `role = 'director'` |
| パスワードリセットメール失敗 | rate limit のことがある。Dashboard から再作成を優先 |
| 部長で他人の案件を編集できない | 正常動作。担当者で新規案件を作成する |

## 通し操作手順（担当者）

**所要目安: 15〜20 分**（初回）

### 1. ログイン → 新規案件

1. ログイン画面で担当者アカウントを入力
2. **新規案件** を作成
   - 工事名はわかりやすい名前（例: 「パイロット試行 7/8」）
   - **評価テーマ**（必須）と **提案の軸（仮）**（任意）を入力
   - **過去実績**・**関連業務メモ**（任意）も Step 2 で入力可能
3. 作成後、自動的に **チェックリスト** タブへ移動

### 2. チェックリスト

1. **PDFをアップロード** — 入札図書 PDF（**4MB 以下**）。または下記 **留意事項テキスト** を入力（どちらか一方以上）
2. **留意事項を保存** — 発注者が明示した評価上の留意点（PDF 無しでも可）
3. **提案の軸を確定** — 入札図書または留意事項を確認したうえで軸を入力または修正
4. **確定して初稿生成へ**

※ 評価テーマあり案件では、入札図書 PDF と提案の軸確定が文案生成の必須条件です

### 3. 文案・Word

1. **生成前チェック** の必須項目が揃っていることを確認
2. **初稿を一括生成** — 生成と同時に **記載ルールチェック（9項目）** が自動実行される
3. （任意）各章の **プレビュー** や **Wordをダウンロード** で内容を確認

### 4. 記載ルールチェック

1. **記載ルールチェック** タブで ○△× を確認（初稿生成時に自動実行済み）
2. 文案を直した場合は **再チェック実行**（または文案タブの **再チェックして記載ルールへ**）
3. △× がある場合は **申請理由** を入力
4. **承認を申請する** → ダイアログで **申請して承認タブへ**

**9項目の例（固定ルール）:** A4 1枚分量、特定情報の非記載、あいまい表現の禁止、概要の簡潔さ、着目点の背景、詳細の具体性、効果の根拠・定量性、新手法の比較 など

### 5. 承認（部長 → 支社長）

1. **ログアウト** → 部長アカウントでログイン
2. 案件一覧から対象案件を開く → **承認** タブ → **承認**
3. **ログアウト** → 支社長アカウントでログイン → 同様に **承認**

### 6. PDF 出力（担当者）

1. 担当者で再ログイン
2. **承認** タブ → **提出版 PDF を出力** → ダウンロード

### 7. 履歴タブ（Phase 4）

**履歴** タブで以下を確認:

- **版履歴**: v1（初稿）、v2（記載ルールチェック）など
- **操作ログ**: 案件作成、提案の軸確定、チェックリスト確定、初稿生成、承認申請、承認 など

※ 公開サイト（Vercel）の時刻は UTC 表示。日本時間より約 9 時間早く見える（データは正しく保存されている）

## よくあるトラブル

| 症状 | 原因 | 対処 |
|---|---|---|
| PDF アップロード失敗 | 4MB 超 | 4MB 以下に圧縮 |
| PDF アップロード失敗 | 他人の案件を開いている | 自分で新規案件を作成 |
| 「この案件を操作する権限がありません」 | 担当者不一致 | 上記と同じ |
| 初稿生成ボタンが押せない | 生成前チェック未達 | チェックリストで PDF・提案の軸を確定 |
| 初稿生成ボタンが押せない | LLM 停止中 | ヘッダーの LLM 停止スイッチを OFF |
| 履歴が空 | SQL 未実行 / 古いデプロイ | `add_case_history.sql` 実行済みか、Vercel Ready 確認 |
| ログイン画面が開かない（ローカル） | dev サーバー停止・固まり | `taskkill /F /IM node.exe` → `npm run dev` |

## パイロットで試さないこと（未実装・制限）

- 新規案件ウィザード Step 2 からの PDF アップロード（チェックリストタブから行う）
- Word を手元で編集して **ファイル再アップロード**（Phase B の「ファイルを選択…」は未実装。再チェックは Storage 上の Word を対象）
- 4MB を超える入札図書 PDF のアップロード（Vercel 制限）
- 採点基準マスタ UI（廃止済み。チェックは固定9ルール）
- 留意事項テキストと PDF の **両方未入力** での文案生成（評価テーマ案件では不可）
